# EVALS

Every result below comes from a real run of the code in this repository. The tables are regenerated by `uv run extensiondesk evals` from the JSON files in `evals/results/`; nothing in them is typed by hand.

## How the evaluation is set up

There are two layers.

**Server contract cases (S01 to S14).** These call the ExtensionDesk MCP server over stdio, exactly as the agent does, but without a language model. They test the guarantees that must hold whatever the model does: no unsourced advice, no invented sources, no release without a named officer, no advice that contradicts the rainfall rules, and messy data flagged instead of silently fixed. They are deterministic.

**Agent cases (A01 to A08).** These run the full LangGraph agent on an open-weights model served locally by Ollama, one cluster and date per run. They test judgement: does the agent pick the right action for the evidence, cite the pest alert, read the officer's notes, and finish within the step limit? The officer gate is answered by the harness, and every such decision is logged under the name "EVAL HARNESS (simulated officer)" so it can never be mistaken for a real approval.

To reproduce:

```bash
uv run extensiondesk evals --server-only   # no model needed
uv run extensiondesk evals                 # needs Ollama and the model, see README
```

## The failure we left unfixed

**S13: Hausa-preferring households do not get the advisory in Hausa.** About three in four synthetic households prefer Hausa. The agent drafts in English and the outbox marks those messages "Hausa version needed before sending", so an officer has to translate before anything goes out. We left this unfixed on purpose. A small model translating agronomic advice into Hausa without review could change the meaning ("plant now" versus "wait"), and in this workflow a wrong instruction is worse than a late one.

What we would try next: keep a short library of officer-approved Hausa templates per action (plant, hold, scout, no advice) with slots for crop and date, have the agent fill the template instead of translating freely, and test it against translations checked by a Hausa-speaking extension officer.

## Known limits of these evals

- The household register, pest alerts and field notes are synthetic. The rainfall is real CHIRPS data, but the Z5 feed gap is injected on purpose (see `data/rainfall/feed_outages.csv`).
- Agent cases are single runs at temperature 0. Small local models can still vary between runs, so a pass here is evidence, not a guarantee.
- The officer gate in agent cases is automated. In real use a person answers it at the prompt, as shown in the demo video.
